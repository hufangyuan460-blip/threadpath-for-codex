# ThreadPath for Codex v0.1.0-beta.5

Beta.5 是继 Beta.3 之后实际完成公开发布的候选版本。相对 Beta.3 的用户可见变化全部来自此前已合入 `main` 的工作；Beta.5 自身只做版本准备、发布说明和一处发布可靠性修复，没有新增用户功能。Beta.5 is the candidate that actually completes publication after Beta.3. Its user-visible changes come from work already merged into `main`; Beta.5 itself only prepares the version, documents the release, and fixes release reliability. It adds no user-facing features.

## 版本历史 / Version history

- Beta.4 标签 `v0.1.0-beta.4` 指向 `27c4dec8324cdecc44fc4b2253084a5f220c4a80`；其 Release 工作流在桌面 E2E 阶段失败，Beta.4 从未公开安装包。标签作为历史记录保留，不删除、不移动、不重新发布。
- Beta.5 包含修复后的 E2E，从干净版本标签重新构建、验收并发布。

- The Beta.4 tag `v0.1.0-beta.4` points at `27c4dec8324cdecc44fc4b2253084a5f220c4a80`. Its Release workflow failed during desktop E2E, so Beta.4 never published an installer. The tag is kept as historical evidence and is neither deleted, moved, nor republished.
- Beta.5 contains the fixed E2E, rebuilt, verified and published from a clean version tag.

## Highlights / 主要改进

- 工作区与会话历史管理：按项目分组浏览、检索、收藏、本地命名与隐藏；左侧工作区在启动和显式历史同步后默认折叠，手动展开只保留在当前应用会话。
- 消息目录与长会话导航：用户输入与模型回复分别进入目录，同回合多段模型回复合为一个入口；分页、虚拟列表与已加载正文检索保持定位。
- 分支讨论与来源定位：从已结束回合创建分支，通过路线图切换同级或嵌套路线，并跳回稳定的源回合与继承历史分界。
- Token Usage 观测：显示服务器累计 total、最近 last 快照、报告窗口，支持 live/resumed/stale/unknown 状态与已观察压缩项；没有数据时不伪造零值。
- 归档与恢复：通过 Codex 归档、保留历史阅读、恢复后续聊；活动会话归档被前端与主进程两层拒绝。
- 历史同步可靠性：区分 notLoaded、summary、full 历史，分页与重读保留已接受输入，仅在服务器回显后去重；未知或缺失终态不再显示为成功。

- Workspace and conversation history management: browse, search, star, rename locally and hide by project. Projects start collapsed and collapse again after explicit history sync; manual expansion lasts for the current app session only.
- Message directory and long-conversation navigation: user inputs and model replies have separate entries, multiple assistant messages in a turn share one entry, and pagination, virtualization and loaded-transcript search keep their position.
- Discussion branches and source navigation: branch from a completed turn, switch between sibling or nested routes on the map, and jump back to the stable source turn and inherited-history boundary.
- Token Usage observation: server-reported cumulative total, latest last snapshot and reported window, with live/resumed/stale/unknown state and observed compactions. Missing data is not replaced with zero.
- Archive and restore: archive through Codex, keep history readable, and restore to continue. Archiving an active conversation is refused by both the UI and the main process.
- History sync reliability: distinguish notLoaded, summary and full history, retain accepted input through pagination and rereads, deduplicate only verified server echoes, and stop showing unknown or missing terminal states as success.

## Release reliability / 发布可靠性

- 发布相关修复只涉及 E2E 验收：活动会话归档原本同时验证「前端禁用按钮」和「主进程复核拒绝」两层保护，旧测试等待一个被正确禁用的按钮变为可用直到超时，导致 Beta.4 的 Release 工作流失败。现在两层保护分别验收，产品行为与安全检查没有放宽，也没有修改业务代码。这是发布可靠性改善，不是新的用户功能。
- 生产门禁不变：标签触发的工作流重新执行类型检查、离线测试、桌面 E2E、正式打包、实际打包 EXE 测试，通过后才发布安装器、构建清单与 SHA-256 校验文件。

- The only release-related fix is in E2E acceptance. Active-conversation archiving protects both the disabled UI action and the main-process rejection; the old test waited for a correctly disabled button to become enabled and timed out, which failed the Beta.4 Release workflow. The two guards are now verified separately. Product behavior and safety checks were not relaxed, and no product code changed. This is release reliability, not a new user feature.
- Production gates are unchanged: the tag-triggered workflow reruns typecheck, offline tests, desktop E2E, the official packaging step and the actual packaged-EXE tests before publishing the installer, build manifest and SHA-256 file.

## Installation / 安装

Windows x64 Beta。从 [GitHub Releases](https://github.com/hufangyuan460-blip/threadpath-for-codex/releases) 选择该版本的安装包、构建清单与 SHA-256 校验文件；先核对来源和校验值。安装并完成 Codex CLI 认证后启动应用，必要时手动选择 CLI 与工作目录。安装包不包含 CLI；校验值以该版本 GitHub Actions 正式发布资产为准，不使用本地开发包摘要。

Windows x64 Beta. Use this version's installer, build manifest and SHA-256 file from [GitHub Releases](https://github.com/hufangyuan460-blip/threadpath-for-codex/releases). Verify its source and checksum. Install and authenticate Codex CLI separately; select its executable and working directory if discovery fails. The CLI is not bundled. Use the checksum of the official GitHub Actions release asset, not a local development package.

## Known Limitations / 已知限制

- Windows x64 Beta；安装包未代码签名；没有自动更新。
- 不包含 Codex CLI，需要用户自行安装、认证和维持网络可用性。
- Observatory 不是精确上下文占用率，不估算剩余上下文、费用、压缩率或 token 节省；total 不等于当前上下文，last 不保证属于整个回合。快照只存内存，重启后未知，单纯浏览历史可能一直没有 Usage。
- `resumed` 是客户端接收路径标签，不证明服务器 replay；历史 contextCompaction 项不证明实时 started/completed。真实 fork Usage 继承、实时压缩完整生命周期、真实重复/null-window 样本和多 resume 对比仍未验证：`M6_C4_FULL_LIFECYCLE: INCOMPLETE`。
- 分支共用源工作目录，没有文件快照、目录隔离或分支合并。
- 该版本未进行实际 NSIS 安装/卸载验收；win-unpacked 合成测试不等于安装流程测试。
- 仓库许可证尚未确定；不宣称已采用 MIT、Apache-2.0 或其他开源许可。

- Windows x64 Beta; unsigned installer; no auto-updates.
- Codex CLI is not bundled. Users must install and authenticate it and provide working network connectivity.
- Observatory does not show exact context occupancy, remaining context, cost, compression ratio or token savings. Total is not current context; last is not necessarily a whole-turn cost. Snapshots are memory-only and unknown after restart; reading history alone may never yield Usage.
- `resumed` labels the client receive path, not proven server replay. Historical compaction items do not prove live started/completed events. Real fork Usage inheritance, the full live compaction lifecycle, duplicate/null-window samples and multi-resume comparison remain unverified: `M6_C4_FULL_LIFECYCLE: INCOMPLETE`.
- Branches share the source working directory; no file snapshots, directory isolation or branch merging.
- Actual NSIS installation/uninstallation has not been validated for this version; win-unpacked synthetic tests do not establish installer-flow success.
- Repository license terms remain undecided; no MIT, Apache-2.0 or other open-source license is claimed.

## Upgrade Notes / 升级说明

面向用户的实际升级路径是 Beta.3 → Beta.5，因为 Beta.4 没有公开安装包。两个版本之间没有修改本地偏好、草稿或分支关系的存储格式，不需要格式迁移；独立工作区选择复用既有工作目录字段，Usage/压缩观测不新增持久化存储。备份个人数据后手动升级；不承诺尚未执行的跨版本安装/卸载验证或自动迁移能力。

The practical upgrade path is Beta.3 → Beta.5, because Beta.4 has no published installer. Between these versions the storage format for preferences, drafts and branch relationships is unchanged, so no format migration is required. Standalone selection reuses existing directory fields, and Usage/compaction observation adds no persistent store. Back up personal data before a manual upgrade. No untested cross-version install/uninstall behavior or automatic migration capability is claimed.
