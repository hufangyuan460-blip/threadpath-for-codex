# ThreadPath for Codex v0.1.0-beta.4

状态 / Status：发布准备 / Release preparation。尚未创建 Beta.4 标签或公开 Release；从 [GitHub Releases](https://github.com/hufangyuan460-blip/threadpath-for-codex/releases) 查看已公开版本。本文依据 `v0.1.0-beta.3..b82911a` 的实际提交，不把验收工具当作新产品功能。

## Highlights / 主要改进

- 支持「不在工作区工作」：使用应用独立工作目录创建会话，保留选择并在未分类历史中浏览；不是无目录执行或工作目录隔离。
- 消息目录区分用户与模型，同回合多段模型消息合为一个回复入口，定位最后一条非空回复；正文不合并、不截断。
- Token Usage 展示服务器累计 total、最近 last 快照及报告窗口，支持 live/resumed/stale/unknown 状态和已观察压缩项；没有数据时不伪造零值。

- Start conversations outside project workspaces using an app-owned working directory, with selection persistence and unclassified history. This is not directory-free execution or workspace isolation.
- Navigate user and assistant messages separately; multiple assistant messages in a turn share one response entry targeting the last non-empty reply, without merging or truncating the transcript.
- Inspect server-reported total/last Token Usage snapshots, reported window, live/resumed/stale/unknown state, and observed compaction items. Missing data is not replaced with zero.

## Reliability Fixes / 可靠性修复

- 未知或缺失终态不再显示为成功；保留兼容性不确定提示。
- 区分 notLoaded、summary、full 历史，分页及重读保留已接受输入，仅在确认服务器回显后去重；弱历史不覆盖更完整的本地内容。
- Usage listener 异常隔离，快照替换而非累加，按线程隔离；正文重读不抹去本进程已观察的压缩状态。
- 分支只读续聊、来源定位与归档恢复沿用已有机制。M6 的专用真实样本补证 fork/历史分页/归档恢复和一次 resume Usage 通知；防重入、报告防覆盖及隐私修复属于验收基础设施，不是新增用户操作。

- Unknown or missing terminal states no longer appear successful; compatibility uncertainty remains visible.
- Distinguish notLoaded, summary and full history; retain accepted input through pagination/rereads and deduplicate only verified server echoes. Weaker history does not overwrite richer local content.
- Isolate Usage listener failures, replace rather than accumulate snapshots, keep threads separate, and retain observed compaction state across transcript rereads.
- Preserve existing read-only branch continuation, source navigation and archive recovery. M6 adds dedicated real-sample evidence for forks/history pagination/archive recovery and one resume Usage notification; acceptance guards and privacy changes are infrastructure, not new user-facing operations.

Windows x64 Beta. Use an actually published installer with its build manifest and SHA-256 file from Releases. Verify its source and checksum. Install and authenticate Codex CLI separately; select its executable and working directory if discovery fails. This preparation-stage development NSIS package is not the future GitHub Actions tag build; its checksum must not be presented as the official release checksum.

## Known Limitations / 已知限制

- Windows x64 Beta；安装包未代码签名；没有自动更新。
- 不包含 Codex CLI，需要用户自行安装、认证和维持网络可用性。
- Observatory 不是精确上下文占用率，不估算剩余上下文、费用、压缩率或 token 节省；total 不等于当前上下文，last 不保证属于整个回合。快照只存内存，重启后未知，单纯浏览历史可能一直没有 Usage。
- `resumed` 是客户端接收路径标签，不证明服务器 replay；历史 contextCompaction 项不证明实时 started/completed。真实 fork Usage 继承、实时压缩完整生命周期、真实重复/null-window 样本和多 resume 对比仍未验证：`M6_C4_FULL_LIFECYCLE: INCOMPLETE`。
- 分支共用源工作目录，没有文件快照、目录隔离或分支合并。
- 本轮未进行实际 NSIS 安装/卸载；win-unpacked 合成测试不等于安装流程测试。
- 仓库许可证尚未确定；不宣称已采用 MIT、Apache-2.0 或其他开源许可。

- Windows x64 Beta; unsigned installer; no auto-updates.
- Codex CLI is not bundled. Users must install and authenticate it and provide working network connectivity.
- Observatory does not show exact context occupancy, remaining context, cost, compression ratio or token savings. Total is not current context; last is not necessarily a whole-turn cost. Snapshots are memory-only and unknown after restart; reading history alone may never yield Usage.
- `resumed` labels the client receive path, not proven server replay. Historical compaction items do not prove live started/completed events. Real fork Usage inheritance, the full live compaction lifecycle, duplicate/null-window samples and multi-resume comparison remain unverified: `M6_C4_FULL_LIFECYCLE: INCOMPLETE`.
- Branches share the source working directory; no file snapshots, directory isolation or branch merging.
- Actual NSIS installation/uninstallation is not tested in this preparation round; win-unpacked synthetic tests do not establish installer-flow success.
- Repository license terms remain undecided; no MIT, Apache-2.0 or other open-source license is claimed.
